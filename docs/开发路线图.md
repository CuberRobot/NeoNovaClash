## 已经做完的版本

### v0.1.0 地基

三层架构（core / web / frontend）、12 角色 9 标签、战斗引擎与事件化战报、房间状态机、
命令行与对拍工具，以及规则 / 架构 / 协议 / 部署 / 版本管理文档。

### v0.3.0 内容扩展到旧项目规模

- 角色池扩到 **20 名**（对齐旧项目 v1.2 的定稿数值）；
- 新增 **吸血 / 反弹 / 斩杀** 三个标签，引擎新增「受击后」结算阶段；
- 测试扩到 57 项。

### v0.4.0 / v0.4.1 平衡与抽池

- `tools/balance.py` 对拍工具（角色抽到率 / 出战率 / 出战胜率 / 标签胜率 / 先手优势）；
- 抽池机制改为「20 张共用抽 12 张 + 462 种切分择优」：双方不重复、两边强度接近；
- 一轮平衡把 **20 名角色全部收敛到 45%~55%**（8000 场对拍），并用测试守住角色差异性；
- 浏览器实测修掉两个真实问题：回放吃掉备战时间、再来一局进不了新对局。

### v0.4.2 打磨版

- 面向玩家：邀请链接、最近战绩、上一局战报回看、倒计时变红提醒、回车提交；
- 鲁棒性：消息大小上限、连接限流、兜底异常、安全响应头、断线自动重连；
- 清理：移除旧手写碎片（出处写进 [项目历史](项目历史.md)），补 [玩家指南](玩家指南.md)。

### v0.5.1 匹配与房间机制

- **随机匹配**：FIFO 队列、可取消、按模式隔离；
- **断线重连**：座位 token + 90 秒宽限，刷新页面自动回到原座位并恢复已提交方案；
- 掉线不再立刻毁房；会话存 sessionStorage（多标签页互不干扰）。

### v0.6.0 / v0.6.1 三种模式与模式隔离

- **模式配置化**：`ModeConfig` 描述池子大小、出战人数、增益次数、随机标签与互斥规则；
- **混沌模式**：角色与标签脱钩，每人 4 个随机标签、单角色最多 2 个；
- **大战场模式**：9 选 5、6 次增益；
- **模式隔离专项**：房间模式以创建者为准、匹配按模式排队、大厅偏好与房间模式分离（均含回归测试）。

## 接下来做什么

**下一阶段的完整计划单独成文：[下一阶段规划（v0.13 → v1.0）](下一阶段规划.md)。**

一句话概括（2026-09-25 的结论）：**稳定性已经达标（连续 6.3 天无重启），
但 20 个访问 IP 只换来 7 场战斗 —— 瓶颈不在玩法数量，而在"来了之后没有第二局"。**

所以顺序是：先补日志（让问题看得见）→ 再做新手路径（v0.13.0）→ 观察一周数据 →
再决定观战 / 电脑对手升级 → 最后收敛到 v1.0。

本文档从此只维护「已经做完的版本」与「现在在哪」，新计划一律写进下一阶段规划。

## 已经闭环的历史问题

| 问题 | 结论 |
| --- | --- |
| 回放吃掉备战时间 | v0.9.0 解决：倒计时等双方 `replay_done` 后再开始（30 秒兜底），备战限时提到 90 秒 |
| 赢了却没有结算页、被踢回大厅 | v0.9.0 解决：房间保存 `final_payload`，重连时随 `state_sync.final` 重新弹出结算页 |
| 死灵法师复活次数 | 1 次 / 30% 血（对拍后由 2 次 / 40% 下调） |
| 双方角色池是否重复 | 不重复：20 张共用抽 12 张后对半切 |
| 中毒是否穿透护盾 | 穿透（直接扣血，不触发护盾与重装） |
| 平衡调整方式 | 先跑对拍再改数值，改动后全部角色必须落在 45%~55% |
