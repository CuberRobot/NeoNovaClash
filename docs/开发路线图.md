# 开发路线图

原则：**先把一条完整链路做扎实，再往上叠内容**。
每个版本都必须满足「main 分支可运行 + 测试全绿 + 文档同步更新」。

---

## v0.1.0 已完成（当前）

- [x] 三层架构落地：游戏核心 / Web 传输 / 前端完全解耦；
- [x] 12 名基础角色、9 种标签的完整实现与边界测试；
- [x] 标准模式完整链路：建房 → 加入 → 备战 → 自动战斗 → 三局两胜 → 再来一局；
- [x] 备战超时自动提交、断线关闭房间、空闲房间回收；
- [x] 事件化战报 + 前端回放（暂停 / 倍速 / 跳到结果）；
- [x] 命令行对战、随机对拍、联机冒烟测试三个开发工具；
- [x] 规则 / 架构 / 协议 / 部署 / 版本管理文档与 Docker 部署文件。

## v0.2.0 体验与可观测性

目标：让「打完一局」变成「有收获的一局」，同时把平衡性调整变成有数据支撑的日常操作。

- [ ] **对局复盘**：战斗结束后可展开完整战报，支持导出为文本 / JSON；
- [ ] **平衡性对拍工具升级**：`tools/cli.py --auto` 输出各角色出场率、胜率、平均存活回合；
- [ ] **关键操作反馈**：提交后显示对手状态，超时前 10 秒给出明显提示；
- [ ] **移动端打磨**：小屏下角色卡与出击位的操作进一步简化；
- [ ] **错误可诊断**：前端错误提示带上 request id，方便对照服务端日志。

验收：能用一份对拍报告说明某个角色是否需要调整；两名玩家在手机上完整打完一局无卡顿。

## v0.3.0 内容扩展：20 角色 / 12 标签

目标：把旧项目文档里已经设计好的内容补齐，且不破坏现有结构。

- [ ] 新增 3 个标签：吸血（命中回复 25%，单次上限 5）、反弹（承伤 40% 反弹，不触发二次效果）、
      斩杀（目标当前血量 ≤ 最大生命 25% 时本次伤害 ×1.5）；
- [ ] 新增 8 名角色：均衡战士D/E、暗影猎手、血怒斗士、晶壁守卫、噬魂者、荆棘守卫、处决者；
- [ ] 角色池随卡池扩大自动生效（无需改前端）；
- [ ] 补充标签互斥与结算顺序文档；
- [ ] 对拍验证新标签不会让某一角色统治环境。

验收：每个新标签至少有 2 条边界测试（触发 / 不触发、上限）；对拍 500 场无异常与死循环。

## v0.4.0 混沌模式

目标：角色与标签脱钩，每局都有新组合。

- [ ] 模式配置化：角色池大小、出战人数、增益次数、是否随机标签都由模式对象决定；
- [ ] 标签分配算法：每人 4 个标签、每个角色最多 2 个、遵守互斥规则（自爆+复活、自爆+吸血、自爆+狂暴、狂暴+重装盔甲）；
- [ ] 自爆步兵不进入混沌角色池；
- [ ] 前端增加模式选择与标签展示；
- [ ] 不同模式的房间互不匹配（房间号加入时校验模式一致）。

验收：连续 100 局混沌模式中，每局标签总数恒为 4 且不出现互斥组合。

---

## v0.5.0 大战场模式

- [ ] 9 选 5、6 次增益、单局最多 5 个出击位；
- [ ] 引擎支持可变队伍规模（当前已按 `len(team)` 循环，只需放开校验与前端布局）；
- [ ] 前端战场布局适配 5 列；
- [ ] 对拍确认大战场不会出现「一边倒」的极端组合。

验收：大战场模式下双方完整打完三局，前端布局在桌面与手机都不溢出。

---

## v0.6.0 联机体验

- [ ] **断线重连**：用 `Player.token` 恢复座位与已提交方案与倒计时；
- [ ] **观战**：房间支持旁观者连接（只收战报，不参与提交）；
- [ ] **随机匹配**：无需房间号的排队匹配；
- [ ] **房间列表**：可看到进行中的公开房间。

验收：刷新页面后 10 秒内自动回到原房间，对手无感知。
