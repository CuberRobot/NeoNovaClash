# 交互与战斗表现层

这份文档说明「玩家怎么操作」和「战斗怎么看」这两件事的设计约定。
规则与数值不在这里，见 [规则设定.md](规则设定.md)。

---

## 一、备战的两种视图

备战页只有**一份状态**（`NC.state.selection / bonuses / strategy`），
两种视图只是同一份状态的两种皮肤，随时切换都不会丢方案。

| 项目 | 卡牌模式（默认） | 按钮模式 |
| --- | --- | --- |
| 上阵 | 把手牌拖到出击位 | 点手牌，自动落到第一个空位 |
| 换位 | 拖动已上阵的卡到另一位 | 点两个出击位互换 |
| 下阵 | 把卡拖回手牌区 | 点位上的「移除」按钮 |
| 增益 | 点筹码 → 点出击位（可连续点多个位置） | 同左 |
| 适合 | 桌面拖顺手、想看牌面 | 手机、键盘操作、不想拖 |

- 视图偏好存在 `localStorage.nc_view`，默认 `cards`；顶部「切到按钮视图 / 切到卡牌视图」随时切换。
- 键盘：`1`~`9` 把对应手牌上阵/收回，`Backspace` 撤销，`Enter` 提交。
- 拖放用 pointer events 自己实现（不是 HTML5 drag & drop），因此鼠标与触屏同一套代码：
  - 鼠标：按下后移动超过 5px 立即开始拖拽；
  - 触屏：长按 150ms 开始拖拽（在此之前滑动页面仍然是滚动）；
  - 拖动结束后用一次 `dragMoved` 标记吞掉紧随其后的 `click`，不会误触发选中。

### 状态机与互斥

- 增益筹码与"点击换位"是两套临时状态，**筹码优先**：手里握着筹码时点位置只会放增益；
- 拿起筹码时自动退出换位状态，避免两个操作互相打断；
- 「只能放第 1 位」的角色（自爆步兵）在任何路径下都会被自动排到首位并提示，包括拖放、换位与随机提交。

### 补卡面板

第二局起，备战页手牌上方会出现一块金色「补卡」面板：3 张候选并排，点一张就收进角色池。

- 点完面板立刻收起、手牌从 6 张变成 7 / 8 张，顶部标题同步显示「7 张 · 7 选 3」；
- 不点也能直接提交（系统随机补一张并明确告知"没选补卡，系统随机补了 XXX"）；
- 补卡只影响自己的池子，对手看不到你补了什么——这正是"猜对手"的一部分。

## 二、战斗回放

### 演出内容

两军左右对峙，自己的阵容永远在左侧（座位 1 的玩家也一样，不需要在脑子里做镜像）：

| 事件 | 表现 |
| --- | --- |
| 回合 / 开战 | 屏幕中央横幅 + 提示音 |
| 近战攻击 | 棋子向敌方冲刺一下 |
| 远程 / 穿透 / 群伤 | 从攻击者飞向目标的弹道，群伤额外震屏 |
| 命中 | 棋子闪红、伤害飘字、血条外圈出现"刚掉了多少"的滞后条 |
| 减伤 / 护盾 | 目标身上出现状态角标（含护盾剩余次数） |
| 中毒 | 紫色角标 + 每回合跳毒飘字 |
| 击杀 | 白屏闪光 + "击杀"标记 |
| 阵亡 | 棋子碎裂成碎片后变灰 |
| 复活 | 死灵法师把队友拉回来（逆过程 + 横幅） |
| 自爆对撞 | 双方一起碎裂、震屏、爆炸音 |
| 本局结束 | 横幅显示胜负，播完弹出本局结算 |

### 播放器原则（重要）

历史上出过一次事故：**整场战斗一瞬间全部播完**。原因是旧实现按"真实时间轴"追赶——
回调里算 `Date.now()` 应该播到第几条，然后把中间的全部一次性刷出来；
浏览器在后台会把定时器降频到 1 秒，回到前台就一次性补完所有事件。

现在的实现（`frontend/js/battle.js`）改成：

1. **逐条推进**：`requestAnimationFrame` 驱动，每次回调最多推进一步，**不做任何时间追赶**；
2. **页面切后台就暂停**：`visibilitychange` 时主动停表并提示，回到前台由玩家决定继续；
3. **整场预算自适应**：每条动作的时长按整场长度缩放，1× 下 3v3 约 15 秒、5v5（130+ 条事件）约 20 秒，
   单条时长限制在 70ms ~ 900ms，致命一击与阵亡额外加权；
4. **玩家始终有控制权**：暂停 / 继续、1×→2×→4×、跳到关键节点（下一个死亡/复活/回合开始）、
   跳到结果、展开战报、重播任意一局。
5. **看演算不占用准备时间**：上一局的 `round_start` 会带 `awaiting_replay=true`，
   客户端在回放结束（或玩家点「跳到结果」）后发一次 `replay_done`；
   服务端等**双方都确认**才开始本局倒计时（最多等 30 秒兜底，防止有人关掉页面把对局卡死）。
   倒计时没开始时，备战页右上角显示「等回放」，不是一个假的数字。

### 战报文本

战斗引擎输出的是结构化事件（`attacker` / `target` / `amount` / `hp_after` / `lethal` / `stacks`…），
表现层只负责"翻译"，不参与计算：**同一个事件既能演出来，也能写成一行文字**，
所以"看战场"和"看战报"永远一致，也不会出现前后端各算一遍的问题。

## 三、音效

- 素材来自 [Kenney.nl](https://kenney.nl) 的 CC0 音效包（Interface / Impact / Sci-Fi / RPG / 8-Bit Jingles），
  共 17 个 `.ogg`、约 280KB，来源与授权写在 `frontend/assets/audio/LICENSE-Kenney.txt`；
- 命名按"发生了什么"而不是"用哪个文件"：`ui-place` / `hit-heavy` / `shatter` / `heal` / `victory` …
  调用方只写 `NC.audio.play("shatter")`；
- 每个音效有独立的基准音量与**最小间隔**（例如普通命中 45ms），5v5 同帧多人出手也不会叠成噪音；
- 浏览器要求先有用户交互才能播放，所以第一次 `pointerdown` / `keydown` 时才预加载并解锁；
- 顶部「🔊 音效 / 🔇 静音」随时开关，偏好存在 `localStorage.nc_sound`。

## 四、这一层的代码结构

前端是**零构建**的原生 JS，按顺序加载五个文件，全部挂在 `window.NC` 上：

| 文件 | 职责 |
| --- | --- |
| `core.js` | 共享状态、DOM 工具、会话（sessionStorage）、最近战绩、棋子与标签素材地址 |
| `audio.js` | 音效表、音量与最小间隔、解锁与开关 |
| `prepare.js` | 备战动作层（上阵/换位/下阵/增益/撤销/提交）+ 两种视图 + 拖放 |
| `battle.js` | 战斗舞台、事件到动画的映射、逐条播放器、战报面板、重播 |
| `app.js` | 大厅、连接、房间与回合流程、消息分发、结算与规则页 |

拆分原则：**动作层只改状态，视图只读状态**。
判断"能不能上阵、能不能放增益"的逻辑只在 `prepare.js` 里写一次，
两种视图、键盘快捷键与将来可能的第三种皮肤都共用它。

改完前端不用手动改版本号：`/static/*` 的 `?v=` 是前端文件的内容哈希
（`frontend_fingerprint()`，带 2 秒缓存），一改就是新 URL，浏览器与 Cloudflare 都不会吃到旧文件。
