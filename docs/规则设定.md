# NeoNovaClash 规则设定

> 适用版本：v0.4.0（标准模式，20 名角色 / 12 种标签，已做完一轮平衡与抽取机制调整）
> 本文是玩法的唯一权威描述；代码里的数值来源在 `backend/core/constants.py`，角色数据在 `backend/core/characters.py`。

---

## 1. 对局结构

| 项目 | 规则 |
| --- | --- |
| 玩家数 | 2 人（各占一个座位，创建房间者为 A 队，加入者为 B 队） |
| 角色池 | 每局从 20 张卡池里**共用抽 12 张，再对半切成两个 6 张池**：双方不会拿到同一名角色，且两边池子强度接近（详见第 6.5 节） |
| 出战人数 | 3 名，**选择顺序即出击顺序** |
| 增益 | 每局 4 次，攻击 +2 或生命 +4；单个出击位最多 2 次 |
| 攻击策略 | 优先攻击当前血量最低 / 攻击力最高 / 指定标签的敌人 |
| 局数与胜负 | 三局两胜（先赢 2 局者胜出） |
| 备战限时 | 60 秒（可通过 `NC_PREPARE_TIMEOUT` 调整），超时由系统随机生成一份合法方案 |
| 单局回合上限 | 50 回合，超过后按剩余总血量判定胜负；血量相同则随机判定 |
| 平局处理 | 双方在同一时刻全灭（例如自爆步兵对撞）判为本局平局，比分不变并重开本局 |

每局开始都会重新抽角色池，因此上一局的角色不会留到下一局。

---

## 2. 一局的完整流程

1. **抽取角色池**：双方各自拿到 6 名角色（只有自己能看到自己池子里的角色）。
2. **玩家备战**
   - 选出 3 名角色（点击顺序决定第 1/2/3 出击位）；
   - 给出击位分配 4 次增益（每位最多 2 次）；
   - 选择攻击策略（若选「优先攻击指定标签」，需再指定一个标签）。
3. **方案校验**（提交时立即校验，不合法会告诉玩家具体哪里不对）
   - 必须恰好 3 名角色、不能重复、必须来自本局角色池；
   - 自爆步兵只能放在第 1 出击位；
   - 增益必须恰好 4 次，且每个出击位不超过 2 次；
   - 策略取值合法；指定标签策略必须给出有效标签。
4. **结算**：双方都提交（或超时自动提交）后一次性演算整场战斗，双方拿到同一份战报。
5. **下一局**：未分出胜负则回到第 1 步，重新抽池，重新备战。

## 3. 战斗结算顺序

### 3.1 开战阶段

1. **标签剥夺**：场上所有诅咒巫师按队伍顺序各触发一次，从敌方仍持有标签的角色中随机选择一名，
   移除其**全部**标签（不会选择敌方诅咒巫师与自爆步兵）。
2. **先手判定**：双方出战角色的先手值总和较小的一方先手；总和相同则随机决定。

### 3.2 回合结构

每个回合依次执行：

1. **回合开始**：结算全场中毒伤害（见 4.8）。
2. **按出击位依次行动**：第 1 位 → 第 2 位 → 第 3 位；
   每个位次中，先手方先出手，然后由对手出手。
3. 已经阵亡的角色跳过其行动。
4. 任意时刻有一方全员阵亡，战斗立即结束（不再打完本回合剩余位次）。

### 3.3 单次攻击的结算顺序

```
选择目标
  → 攻击方修正（狂暴、斩杀）
  → 自爆判定（直接击杀 / 同归于尽）
  → 护盾分担（护盾部署者为队友承担 50%）
  → 受击方修正（重装盔甲减伤）
  → 扣血与阵亡判定（触发复活）
  → 受击后效果（反弹）
  → 命中后效果（中毒叠加、箭矢穿透追击、吸血回复）
  → 自爆反噬（出手者死亡）
```

取整规则：所有比例一律**向下取整**（整数运算），保证不同平台结果一致。

## 4. 标签效果

### 4.1 自爆（自爆步兵）

- 出手后自身立即死亡，属于一次性兵器；
- 若目标**最大生命 ≤ 26**，直接击杀该目标；否则按自身攻击力结算普通伤害；
- 自爆伤害**不参与护盾分摊**、不触发反弹；
- 自爆步兵**不可被复活**，且只能放在第 1 出击位；
- 若双方的自爆步兵互相攻击，则同归于尽（双方都死亡，判为本局平局）。

### 4.2 复活（死灵法师）

- 只要死灵法师**存活且还有次数**，任何队友阵亡时立刻触发；
- 复活生命 = 最大生命的 **40%**（向下取整）；
- 自爆步兵不可被复活；死灵法师死亡后能力立即失效，也无法复活自己；
- 每局次数：2 次。

### 4.3 标签剥夺（诅咒巫师）

- 开战时触发一次；
- 从敌方仍有标签的角色中随机选一名，移除其全部标签；
- 不会选择敌方诅咒巫师与自爆步兵作为目标；
- 若敌方没有可剥夺的目标，会在战报中说明。

### 4.4 护盾（护盾部署者）

- 队友受到伤害时，护盾部署者为队友承担 **50%** 伤害；
- 转移到自己身上的伤害仍会走自身承伤流程（重装盔甲减伤仍然生效），但不会被再次分担；
- 自爆伤害不可分担；护盾部署者不能为自己分担；
- 每局次数：3 次，用尽后不再分担。

### 4.5 重装盔甲（铁甲卫士）

- 单次受到 **≥7** 点伤害时触发，该次伤害按 **60%** 结算（向下取整）；
- 中毒等持续伤害不触发。

### 4.6 箭矢穿透（风行射手）

- 若本次攻击的主目标**最大生命 ≤ 24**（脆皮判定），则对**该目标之外**随机一名存活敌人追加一次 **50%** 伤害的攻击；
- 追击伤害会正常被护盾分担、被重装盔甲减伤，但不会再次触发穿透、中毒、吸血与反弹；
- 判定依据是主目标的**最大生命**，与主目标是否阵亡无关。

### 4.7 狂暴（狂战士）

- 自身出手瞬间血量 **≤14** 时，本次伤害 ×1.4（向下取整）；
- 同一回合内多次攻击会分别按当时的血量判定。

### 4.8 中毒（毒药投手）

- 每次命中使目标毒层 +1，每层每回合造成 **3** 点伤害，持续 **3** 回合；
- 层数上限 **3**；达到上限后再命中会刷新「最快到期的一层」，不会继续叠层；
- 每回合开始时统一结算：伤害 = 3 × 当前层数；
- 中毒伤害**直接扣血**，不经过护盾与重装盔甲，但会正常触发阵亡与复活判定。

### 4.9 群伤（重炮统领）

- 出手时不再选择单一目标，而是对敌方**所有存活单位**各结算一次伤害；
- 每个目标分别计算攻击方修正（狂暴、斩杀等），也分别触发护盾、重装盔甲与反弹。

### 4.10 吸血（噬魂者）

- 每次命中后，按本次**实际造成伤害**的 25%（向下取整）回复自身生命，单次最多回复 5 点；
- 自爆伤害不触发吸血；箭矢穿透的追击伤害同样不触发；
- 回复量以自身最大生命为上限，不会溢出。

### 4.11 反弹（荆棘守卫）

- 受到伤害后，按本次**实际损失生命**的 40%（向下取整）反弹给攻击者；
- 被这一击打死的当次同样会反弹（先结算伤害与阵亡，再结算反弹）；
- 反弹伤害的规则：**不经过护盾分摊、不受重装盔甲减免、不会被再次反弹**；
- 自爆伤害不会被反弹。

### 4.12 斩杀（处决者）

- 出手瞬间若目标的**当前生命 ≤ 最大生命的 25%**，本次伤害提升至 150%（向下取整）；
- 判定只看目标当前生命与最大生命，与自身状态无关；
- 与狂暴（A 队同时拥有两种标签时）可以叠加，按顺序相乘后取整。

## 6. 攻击策略与抽池机制

### 6.1 攻击策略

| 策略 | 目标选择 |
| --- | --- |
| 优先攻击当前血量最低的敌人 | 取当前 HP 最小者；HP 相同时按出击位靠前者优先 |
| 优先攻击攻击力最高的敌人 | 取 ATK 最大者；ATK 相同时取 HP 更低者，再按出击位 |
| 优先攻击指定标签的敌人 | 优先从带有该标签的敌人中选 HP 最低者；若敌人都不带该标签，则退回「血量最低」 |

群伤角色（重炮统领）不使用目标选择，直接覆盖敌方全体。

自爆步兵有额外的战术选择：**优先炸掉「能被直接击杀（最大生命 ≤ 自爆击杀线）」里攻击力最高的敌人**；
如果没有可击杀目标，才回到玩家设定的攻击策略。

### 6.2 抽池机制（v0.4.0 起）

1. **共用抽池**：从 20 张里均匀抽 12 张（每名角色的被抽概率相同），再对半切成两个 6 张池，
   因此双方不会拿到同一名角色，也不会出现镜像对局；
2. **构筑空间约束**：每个池子至少有 2 名带标签的角色，同一标签最多 2 名
   （避免「六个白板」或「清一色同标签」的无聊池子）；
3. **强度均衡**：在 12 张卡的所有对半切分（462 种）里挑最公平的一种，
   让两边的先手值总和、总生命、总攻击尽量接近，避免开局就因为池子强弱失衡。

> 实现细节：抽样与切分是刻意分开的两步。如果只用「反复重抽直到公平」，
> 像自爆步兵这种数值离群的角色会因为拖低公平分数而被系统性筛掉
> （实测它的出场率会从 30% 掉到 17.8%），所以改成「均匀抽样 + 枚举最优切分」。

## 7. 数值裁定（与旧文档冲突时的处理）

旧项目前后有多次平衡调整，文档之间存在冲突。v0.1.0 的取值与理由如下：

| 项目 | 取值 | 说明 |
| --- | --- | --- |
| 自爆击杀线 | 目标最大生命 ≤26 | 采用 v1.1 调整后的数值（最初为 ≤24） |
| 自爆步兵生命 | 3 | 采用 v1.1 调整后的数值（最初为 1） |
| 复活血量 | 最大生命 40% | 采用设定文档 `设定.md` 与 v1.1 的说法；v1.2 更新日志里的「30%」与之一致性较差，暂不采用 |
| 复活次数 | 2 次 | 碎片实现中按队伍统计 2 次；v1.2 曾下调为 1 次，保留 2 次以便先观察平衡 |
| 重装盔甲 | ≥7 伤害 → 60% | 采用设定文档（v1.2 更新日志里的「≥6」为一次未落地的调整） |
| 护盾 | 50% 分担 3 次 | 两份文档一致 |
| 中毒 | 每层 3 点 / 3 回合 / 最多 3 层 | 采用实现常量，文档未细化 |
| 均衡战士C | ATK 5 | 采用 v1.2 的加强 |
| 重炮统领 | ATK 4 | 采用 v1.2 的削弱 |
| 晶壁守卫 / 荆棘守卫 | ATK 4、HP 28 | 采用 v1.2 的加强（原为 ATK 3） |
| 吸血 | 伤害的 25%，单次上限 5 | v1.2 新增标签，两份文档一致 |
| 反弹 | 实际伤害的 40% | 采用 v1.2 调整后的数值（v1.1 为 30%） |
| 斩杀 | 目标 ≤ 最大生命 25% 时 ×1.5 | v1.2 新增标签，两份文档一致 |
| 先手值 | 见第 5 节表格 | 采用 v1.2 调整后的数值 |
| 双方角色池 | 独立随机 | 碎片实现即为各自 `sample`，简单且与文档「各自获得随机角色池」一致 |

任何数值调整都应同时更新本节、`CHANGELOG.md` 与 `backend/core/constants.py`。

### 7.1 v0.4.0 平衡调整（基于 8000 场对拍）

第一轮平衡用 [tools/balance.py](../tools/balance.py) 跑了 8000 场随机对拍，
以「出战胜率落在 45%~55%」为目标，遵循两条原则：

1. **保住人设**：不动角色的定位与面板曲线，只在其定位允许的范围内微调；
2. **用先手值当补偿**：强角色把先手值调高（更难抢到先手），弱角色调低。

| 项目 | 调整 |
| --- | --- |
| 死灵法师 | 复活次数 2 → **1**，复活血量 40% → **30%**（原版胜率 79%，过于强势） |
| 重装盔甲 | 减伤比例 60% → **70%**（重装系整体偏强） |
| 自爆步兵 | 击杀线 26 → **30**，攻击 16 → **18**，并新增「优先炸可击杀的高攻目标」的战术选择（原版胜率 41%） |
| 护盾部署者 | 攻击 2 → **3**，护盾次数 3 → **4**（原版胜率 33%） |
| 中毒 | 每层每轮伤害 3 → **2**（毒药投手偏强） |
| 抽池机制 | 从「各自独立抽 6 张」改为「共用抽 12 张后对半切 + 强度均衡」（见 6.2） |
| 其余角色 | 逐个按对拍数据微调 ATK/HP/先手值，收敛到 45%~55% 区间 |

调整后（8000 场）：20 名角色全部落在 45%~55%，A/B 两队胜率 3975:3999，
平均 6.7 回合、最长 16 回合，平局率 0.3%。先手方胜率约 55%，
这是「先手值换强度」机制的固有代价，保留作为后续观察项。

## 9. 如何复现一场战斗

每局战斗的种子会写进战报（`result.seed`），相同阵容 + 相同策略 + 相同种子 = 完全相同的战报：

```bash
./venv/bin/python -m tools.cli --auto 1 --seed 20260918    # 随机对拍，可指定种子
./venv/bin/python -m tools.cli                            # 手动摆阵容，逐条读战报
```

在测试里，`tests/test_engine.py::test_battle_is_reproducible_with_same_seed` 会持续守住这条性质。
