# 开发流程与版本管理

这份文档存在的唯一目的：**让项目永远能回到一个可运行的稳定版本**。
之前的两次尝试之所以走不下去，是因为改动太大、提交太粗，出了问题没有干净的落点。

---

## 1. 分支模型

```text
main                    始终可运行，随时可以部署
 ├─ feat/<主题>          新功能：例如 feat/chaos-mode
 ├─ fix/<主题>           修 bug：例如 fix/room-cleanup
 └─ release/<版本>       发版前的收尾（可选）
legacy/novaclash2       被放弃的旧实现，只读保留，用于对照
```

| 规则 | 说明 |
| --- | --- |
| `main` 只接受通过测试的合并 | 合并前必须 `pytest` + `ruff` 全绿 |
| 一个分支只做一件事 | 主题变了就开新分支，别在同一个分支里塞两个功能 |
| 分支存活时间尽量短 | 长时间分支必然产生难解的冲突 |
| 合并方式 | 优先 `--no-ff` 合并保留分支轨迹，或直接快进合并 |

常用命令：

```bash
git switch -c feat/chaos-mode        # 开分支
git add -A && git commit -m "feat(rules): 支持随机标签角色池"
git switch main && git merge --no-ff feat/chaos-mode
git branch -d feat/chaos-mode
```

## 2. 提交规范

格式：`类型(范围): 说明`，说明写清「做了什么、为什么」，一次提交只做一件事。

| 类型 | 用途 |
| --- | --- |
| `feat` | 新功能 |
| `fix` | 修 bug |
| `docs` | 文档 |
| `test` | 测试 |
| `refactor` | 不改变行为的重构 |
| `perf` | 性能 |
| `chore` | 依赖、配置、构建 |

范围建议：`engine` / `rules` / `room` / `web` / `ui` / `tools` / `docs` / `deps`。

```text
feat(engine): 新增斩杀标签的伤害修正
fix(web): 对手掉线后房间没有立即回收
docs(rules): 记录复活次数取 2 的原因
test(engine): 覆盖自爆对撞的同归于尽分支
```

**什么时候必须提交**：

- 写完一个可运行的小步骤（哪怕只是一个标签效果）；
- 修好一个 bug，并且补上了对应的测试；
- 调整了平衡数值（同时更新 `docs/规则设定.md` 与 `CHANGELOG.md`）。

**什么时候不要提交**：测试没跑通、功能做了一半无法运行、把无关改动混在一起。

## 3. 里程碑与 tag

每个可玩的里程碑打一个 tag，tag 就是「可以一键回去的点」。

```bash
git tag -a v0.2.0 -m "v0.2.0：扩展角色与吸血/反弹/斩杀"
git push origin main --tags
git tag -l                        # 查看所有稳定点
```

已经建立的里程碑：

| tag | 内容 |
| --- | --- |
| `v0.1.0` | 标准模式完整可玩：12 角色 / 9 标签 / 联机三局两胜 |

## 4. 发布检查清单

发版（打 tag）前逐项打勾：

- [ ] `./venv/bin/python -m pytest -q` 全绿；
- [ ] `./venv/bin/ruff check .` 无告警；
- [ ] 改了前端 JS 时 `node --check frontend/js/app.js` 通过；
- [ ] 用 `tools/smoke_pvp.py` 在真实服务上跑完一整套三局两胜；
- [ ] 手动点一遍：创建房间 → 加入 → 备战 → 提交 → 战斗回放 → 结算 → 再来一局；
- [ ] 更新 `CHANGELOG.md` 与 `docs/规则设定.md`（若有数值变化）；
- [ ] 更新 `docs/开发路线图.md` 的完成状态；
- [ ] `git status` 干净，没有忘记加的文件；
- [ ] 打 tag 并推送：`git push origin main --tags`。

## 5. 回滚剧本

### 5.1 线上出问题，但想保留历史

```bash
git log --oneline -10              # 找到出问题的提交
git revert <commit>                # 生成一条反向提交
git push origin main
```

`revert` 会留下记录，团队能看到「什么被撤回了」，推荐优先使用。

### 5.2 本地改乱了，想回到稳定版本

```bash
git switch main
git fetch --tags
git checkout v0.1.0                # 直接回到稳定版本（只读观察）
git switch -c fix/rollback         # 想在此基础上继续改就开分支
```

### 5.3 只想撤销工作区里没提交的改动

```bash
git status                         # 先看清楚动了哪些文件
git restore <文件>                  # 丢弃指定文件的改动
git restore --staged <文件>          # 撤销暂存
```

> 危险操作（`git reset --hard`、`git checkout -- <文件>`）会直接丢数据，
> 只有在确认没有未提交成果时才使用。

### 5.4 想找回几天前删掉的代码

```bash
git log --oneline --all -- <路径>          # 找到涉及该文件的提交
git show <commit>:<路径>                   # 查看当时的完整内容
git checkout <commit> -- <路径>            # 把文件恢复到工作区
```

### 5.5 想对照被放弃的旧实现

旧实现（FastAPI + 前端单页）保留在 `legacy/novaclash2` 分支：

```bash
git show legacy/novaclash2:server/game/engine.py | less
git show legacy/novaclash2:README.md
```

> 注意：旧实现本身有问题（数值与文档不一致、结构耦合），只作为对照，不要直接回退。

## 7. 日常开发流程示例

### 7.1 调整平衡数值

```bash
git switch -c feat/balance-v0.2
# 1. 只改 backend/core/constants.py
# 2. ./venv/bin/python -m tools.cli --auto 200   # 看胜率是否健康
# 3. 更新 docs/规则设定.md 的数值表与 CHANGELOG.md
# 4. pytest + ruff
git commit -m "feat(balance): 狂战士狂暴倍率 1.4 → 1.5，并记录对拍结果"
```

### 7.2 新增标签

```bash
git switch -c feat/tag-lifesteal
# 1. tags.py 注册 TagSpec 与 TagRuntime（吸血 = on_hit 钩子）
# 2. characters.py 里挂到噬魂者身上
# 3. tests/test_engine.py 补边界用例（回复上限、自爆不触发）
# 4. docs/规则设定.md 补标签说明与结算顺序
git commit -m "feat(engine): 新增吸血标签（25% 回复，单次上限 5）"
```

### 7.3 修 bug

```bash
git switch -c fix/room-cleanup
# 1. 先写一条会失败的测试，确认它确实复现了问题
# 2. 改实现让测试通过
git commit -m "fix(web): 修复房间长时间无活动未被回收的问题"
```

## 8. 不进入版本库的内容

`.gitignore` 已经覆盖：虚拟环境（`venv/`）、`__pycache__`、本地配置（`.env`）、
编辑器与系统文件（`.DS_Store` / `.idea` / `.vscode`）、运行产物（`logs/`、`data/`、`*.log`）。

需要新增忽略项时，优先在 `.gitignore` 里加规则，而不是把文件手动移出目录。
