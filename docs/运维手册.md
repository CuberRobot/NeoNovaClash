> 适用版本：v0.12.0（本文描述的是**部署与运维**，与玩法版本无关，按仓库规矩不抬版本号）

本文记录这台线上服务器怎么跑、怎么查、怎么回滚。

## 1. 常用检查

```bash
# 服务活着吗（本机）
systemctl status neonovaclash --no-pager
curl -fsS http://127.0.0.1:8010/api/health

# 从外网（经 Cloudflare）
curl -fsS https://novaclash.cc/api/health

# 通过 nginx 走一遍（确认反代与 Host 路由正常，不经过 CDN）
curl -fsS -H "Host: novaclash.cc" -o /dev/null -w "%{http_code}\n" http://127.0.0.1/

# 隧道在不在
systemctl is-active cloudflared
```

`/api/health` 会返回 `rooms` / `players` / `queue` / `totals`
（`rooms_created`、`rooms_closed`、`battles_played`），重启会清零。

## 2. SSH：只用密钥，没有密码

2026-09-25 起：

- `PasswordAuthentication no`、`KbdInteractiveAuthentication no`、`PermitRootLogin prohibit-password`；
- 配置落在 `/etc/ssh/sshd_config.d/00-novaclash-hardening.conf`（**优先级高于 jumpcloud 的 `50-*.conf`**，
  所以不会被它重新打开密码登录）；
- 密钥：本地 `~/.ssh/id_ed25519`，公钥在服务器 `/root/.ssh/authorized_keys`；
- 仓库自带 `.ops/ssh_run.py` 已改为**密钥优先**，日常运维这样用：

```bash
python .ops/ssh_run.py 'systemctl status neonovaclash --no-pager'
python .ops/ssh_run.py --put 本地文件 远端路径
```

**注意**：仓库里不再需要、也不应该出现服务器密码。已经用过密码的地方请轮换一次。
后路：宝塔面板控制台 / 云厂商 VNC 都能进去，即使密钥丢了也不会把自己锁死在外面。

### 2.1 fail2ban

```bash
fail2ban-client status sshd          # 看当前封了哪些 IP
fail2ban-client set sshd unbanip <IP>   # 误封了就解
```

配置在 `/etc/fail2ban/jail.d/novaclash.local`：10 分钟内失败 3 次封 12 小时，`127.0.0.1` 与 `::1` 白名单。
禁用的当天，日志里累计有 3.7 万次 `Failed password` + 1.9 万次 `Invalid user`。

## 3. 应用日志

### 3.1 落在哪里

systemd 直接把进程的 stdout/stderr 接进文件（`deploy/neonovaclash.service`）：

```ini
StandardOutput=append:/www/wwwlogs/neonovaclash.app.log
StandardError=append:/www/wwwlogs/neonovaclash.app.log
```

轮转由 `/etc/logrotate.d/neonovaclash` 负责（模板在 `deploy/logrotate/neonovaclash`）：

```
daily / rotate 14 / compress / copytruncate / su www www / create 0640 www www
```

> 为什么用 `copytruncate`：systemd 以 append 打开文件，`create` 之后它仍持有旧 inode 的 fd，
> 日志会继续写进已经改名的旧文件。`copytruncate` 保证服务不用重启。

演练轮转（只打印会做什么，不动文件）：

```bash
logrotate -d /etc/logrotate.d/neonovaclash
```

### 3.2 关键事件日志（结构化，直接 grep）

| 事件 | 含义 | 字段 |
| --- | --- | --- |
| `room_created` | 有人开房 / 开始练习 / 匹配凑成一桌 | `room=` `mode=` `source=` `prepare_timeout=` |
| `matchmaking_waiting` | 有人进匹配队列 | `player=` `mode=` `queue_size=` |
| `matchmaking_matched` | 匹配成功 | `pair=` `waited=` |
| `battle_start` | 某一局开打 | `round=` `seed=` `players=` |
| `match_over` | 整场三局两胜结束 | `winner=` `score=` `rounds=` `players=` |
| `room_closed` | 房间关闭（离开/掉线超时/空闲回收） | `reason=` `rounds_played=` |

一场完整的对局长这样：

```text
2026-09-25 22:01:45 INFO neonovaclash.hub | room_created room=KABH mode=standard source=create_room prepare_timeout=90s
2026-09-25 22:01:45 INFO neonovaclash.hub | battle_start room=KABH mode=standard round=1 seed=1228020546 players=机器人A vs 机器人B
2026-09-25 22:01:45 INFO neonovaclash.hub | battle_start room=KABH mode=standard round=2 seed=1228028465 players=机器人A vs 机器人B
2026-09-25 22:01:45 INFO neonovaclash.hub | match_over   room=KABH mode=standard winner=1 score=0 2 rounds=2 players=机器人A vs 机器人B
```

"昨天有多少人开房、打完几局" 一句话回答：

```bash
grep -c room_created  /www/wwwlogs/neonovaclash.app.log
grep -c match_over    /www/wwwlogs/neonovaclash.app.log
grep 'room_closed'    /www/wwwlogs/neonovaclash.app.log | tail   # 人是从哪一步走的
```

日志**只带昵称与房间号**，不含 token、角色池或任何私有对局数据。

## 4. 改配置：先看这里再动手

`deploy/neonovaclash.service` 里的每个 `Environment=` 都会**覆盖** `backend/config.py` 的默认值：

| 变量 | 线上值 | 说明 |
| --- | --- | --- |
| `NC_HOST` / `NC_PORT` | `127.0.0.1` / `8010` | 只监听回环，对外交给 nginx |
| `NC_PREPARE_TIMEOUT` | `90` | 备战限时，与《规则设定》一致（2026-09-25 前是 60，已纠正） |
| `NC_RECONNECT_GRACE` | `90` | 掉线重连宽限 |
| `NC_ROOM_TTL` | `1800` | 空闲房间回收 |
| `NC_MAX_ROOMS` | `200` | 单进程房间上限 |
| `NC_LOG_LEVEL` | `info` | 日志级别 |

> 历史坑：曾经 unit 里写 `NC_PREPARE_TIMEOUT=60`，而文档和代码默认都是 90，
> 结果线上玩家只拿到 60 秒备战。改任何 `Environment=` 之前先跟 `backend/config.py` 对一眼。

## 5. 更新与回滚

```bash
cd /www/wwwroot/neonovaclash
bash deploy/update.sh          # git pull --ff-only + 装依赖 + 重启 + 健康检查
```

回滚到某个 tag：

```bash
git fetch --tags && git checkout <tag> && bash deploy/update.sh
```

**注意**：`deploy/update.sh` 不会覆盖 `/etc/systemd/system/neonovaclash.service`。
如果这次改动同时动了 unit（比如新增环境变量、日志落盘），要手动：

```bash
cp deploy/neonovaclash.service /etc/systemd/system/neonovaclash.service
install -m 644 deploy/logrotate/neonovaclash /etc/logrotate.d/neonovaclash
chown www:www /www/wwwlogs/neonovaclash.app.log
systemctl daemon-reload && systemctl restart neonovaclash
```

unit 的回滚点：改动前的备份在 `/root/neonovaclash.service.bak-<时间戳>`。

## 6. 常见问题

| 现象 | 先看什么 |
| --- | --- |
| 域名打不开 / 522 | `systemctl status cloudflared`（隧道断了，源站不受影响） |
| 502 | `systemctl status neonovaclash` + `ss -lntp \| grep 8010` |
| 页面停在"连接中…" | nginx 的 `Upgrade`/`Connection` 头；`/ws` 是否被 Cloudflare 缓存 |
| 玩家说"进不去房间" | `grep room_closed app.log`（房间是不是被回收/掉线关掉了） |
| 想知道昨天来了多少人 | `grep -c room_created app.log`；nginx 日志里 404 绝大多数是扫描器，别被吓到 |
| 日志文件不增长 | `systemctl show -p StandardOutput neonovaclash`，以及文件属主是否是 `www:www` |
| 磁盘 | `df -h /`（30G 盘，日志每天轮转留 14 天，正常不会满） |
