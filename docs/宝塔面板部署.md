# 宝塔面板部署（含 WebSocket 反代）

本文记录的是「用一台装了宝塔面板的 Linux 服务器，把 NeoNovaClash 跑成可对外访问的 demo」
这套做法，也是本项目线上 demo 当前使用的方案。**文中不包含任何服务器密码或面板凭据**，
凭据请只保存在你自己的密码管理器里。

## 0. 部署结构

```text
浏览器
  │  http://<服务器IP>/            （WebSocket 走同一端口的 /ws）
  ▼
宝塔自带的 nginx :80
  │  反向代理（带 WebSocket 升级头）
  ▼
127.0.0.1:8010   ← systemd 服务 neonovaclash（www 用户）
  │
/www/wwwroot/neonovaclash   ← 代码 + venv
```

要点：应用只监听回环地址，对外只暴露 80（或你申请的域名 + 443），
这样既不用额外开放端口，也能让宝塔面板统一管理证书与访问日志。

## 1. 前置检查

```bash
cat /etc/os-release | head -2      # 本文以 Debian 12 为例
python3 -V                         # 需要 3.10+，推荐 3.11/3.12
nginx -v                           # 宝塔自带 nginx 即可
ls /www/server/panel              # 确认宝塔面板存在
```

如果 `python3 -m venv` 报 `No module named 'ensurepip'`，先补依赖：

```bash
export DEBIAN_FRONTEND=noninteractive
apt-get update -qq
apt-get install -y python3-venv python3-pip
```

## 2. 拉代码并创建虚拟环境

```bash
mkdir -p /www/wwwroot
git clone https://github.com/CuberRobot/NeoNovaClash.git /www/wwwroot/neonovaclash
cd /www/wwwroot/neonovaclash

python3 -m venv venv
venv/bin/pip install --upgrade pip
venv/bin/pip install -r requirements.txt
```

自检（可选，建议第一次部署都跑一遍）：

```bash
venv/bin/python -m pytest -q          # 需要先 pip install -r requirements-dev.txt
```

## 3. 注册 systemd 服务

仓库里已经准备好了服务模板 [deploy/neonovaclash.service](../deploy/neonovaclash.service)：

```bash
cp /www/wwwroot/neonovaclash/deploy/neonovaclash.service /etc/systemd/system/neonovaclash.service
chown -R www:www /www/wwwroot/neonovaclash
systemctl daemon-reload
systemctl enable --now neonovaclash
systemctl status neonovaclash --no-pager
```

两个容易踩的坑：

1. **必须用 `python run.py` 启动**，不要写成 `uvicorn backend.web.app:app`。
   uvicorn 命令行不会读取 `NC_HOST` / `NC_PORT` 环境变量，会默认监听 127.0.0.1:8000，
   于是 nginx 反代到 8010 就会连不上。
2. **不要加 `--workers`**。房间状态存在进程内存里，多进程会让同一名玩家的两次连接落到不同进程。

验证：

```bash
ss -lntp | grep 8010                          # 应该看到 127.0.0.1:8010
curl -fsS http://127.0.0.1:8010/api/health    # {"status":"ok",...}
```

## 4. 配置 nginx 反向代理

仓库里的模板：[deploy/nginx.neonovaclash.conf](../deploy/nginx.neonovaclash.conf)

```bash
cp /www/wwwroot/neonovaclash/deploy/nginx.neonovaclash.conf \
   /www/server/panel/vhost/nginx/neonovaclash.conf

nginx -t && nginx -s reload
```

模板里最关键的是这几行，**缺了 WebSocket 头，前端会一直停在「连接中…」**：

```nginx
proxy_http_version 1.1;
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
proxy_read_timeout 300s;
```

### 想用宝塔面板界面来做也行

1. 面板 → **网站** → 添加站点（域名填服务器 IP 或你的域名，不要选 PHP）；
2. 进入该站点 → **反向代理** → 添加反向代理：
   - 代理名称：`neonovaclash`
   - 目标 URL：`http://127.0.0.1:8010`
   - 发送域名：`$host`
   - **务必勾选「开启 WebSocket 支持」**；
3. 需要 HTTPS 时，在同一站点里申请 Let's Encrypt 证书即可，
   前端会自动使用 `wss://`（代码按 `location.protocol` 判断），不用改任何配置。

## 5. 验收

```bash
# 服务器本机
curl -fsS -H "Host: <服务器IP>" http://127.0.0.1/api/version

# 从你自己的电脑
curl -fsS http://<服务器IP>/api/health

# 用两个机器人客户端在线上跑完整场三局两胜（本仓库自带）
python -m tools.smoke_pvp --url ws://<服务器IP>/ws

# 最真实的一步：用两个浏览器标签页各开一局，确认：
#   大厅 → 创建/加入房间 → 选人布阵 → 战报回放 → 比分结算 → 再来一局
```

如果外网打不开但服务器本机 `curl` 正常，问题通常在**云厂商的安全组**里没有放行 80/443。

## 6. 更新与回滚

仓库提供了一键更新脚本 [deploy/update.sh](../deploy/update.sh)：

```bash
bash /www/wwwroot/neonovaclash/deploy/update.sh
# 等价于：git pull --ff-only && pip install -r requirements.txt && systemctl restart neonovaclash && 健康检查
```

脚本会先执行 `git config --global --add safe.directory "$APP_DIR"`：
用 root 操作 `www` 用户拥有的目录时，git 默认会以「dubious ownership」拒绝执行。

回滚到某个稳定版本（tag）：

```bash
cd /www/wwwroot/neonovaclash
git fetch --tags
git checkout v0.1.0
bash deploy/update.sh
```

## 7. 宝塔面板里还能做什么

| 需求 | 在面板里的位置 |
| --- | --- |
| 看服务是否在跑、重启 | 终端里 `systemctl status/restart neonovaclash`（面板不显示自定义 systemd 服务） |
| 看访问日志 | 面板 → 网站 → 站点 → 日志；或 `/www/wwwlogs/neonovaclash.log` |
| 配置域名与 HTTPS | 网站 → 站点 → 域名管理 / SSL |
| 控制端口开放 | 面板 → 安全（同时别忘了云厂商控制台的安全组） |
| 升级 Python 依赖 | 终端执行 `deploy/update.sh` |

## 8. 安全注意事项

- **面板凭据不要进仓库**：本文档与仓库里没有任何密码；也请勿把服务器密码写进
  `.env`、README 或提交信息。建议面板开启「面板 SSL + 二次验证 + IP 白名单」，
  并避免把面板端口暴露在公网。
- **demo 目前没有登录鉴权**：任何知道地址的人都能创建房间（房间里只有对局数据）。
  如果要长期公开，建议加一层 nginx Basic Auth 或在应用里加房间密码。
- **443 未开放时不要用 https 访问**：会一直连接超时；要么在云安全组放行 443 并用面板申请证书，
  要么就用 http。
- **房间是内存态**：重启服务会清空所有房间，玩家需要重新建房（重连功能在路线图里）。
- 建议给 demo 设一个较低的 `NC_MAX_ROOMS`（模板里是 200），防止被刷房间占满内存。

## 9. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 页面停在「连接中…」 | nginx 缺 WebSocket 升级头 | 按第 4 节补 `Upgrade` / `Connection` |
| 502 Bad Gateway | 应用没在 8010 监听 | 用 `python run.py` 启动；`ss -lntp \| grep 8010` 确认 |
| 外网完全打不开 | 云厂商安全组没放行 | 安全组放行 80（以及 443） |
| 加入房间提示「房间不存在」 | 房间号错误、对手已离开、或服务重启过 | 重新建房 |
| 刚进对战就被自动提交 | 备战超时（默认 60 秒） | 调大 `NC_PREPARE_TIMEOUT` 后重启服务 |
| 两人互相看不到对方 | 两人连的不是同一个实例 | 确认访问同一个地址 |
